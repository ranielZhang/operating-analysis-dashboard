## 1. 做完之后要能回答的四件事

1. 这段时间的经营利润有没有达到预算。
2. 利润来自自研运营、游戏出售、外部发行投放中的哪一类。
3. 自研项目盈利后，研发侧和发行侧各归属多少。这是内部归属，公司利润不被减掉。
4. 可动用现金还能支撑几个月，老游戏的经营结果能不能盖住新项目投入。

## 2. 实施前锁死的演示口径

下面这些规则直接写进 `src/domain/store.ts` 的计算处，并在对应卡片上用一行字标出来。不再留成待确认项。

| 项 | 规则 |
|---|---|
| 项目利润 | 确认收入 − 研发投入 − 发行投放 − 其他直接成本 |
| 五五 | 仅自研、且项目利润 > 0 时，研发侧归属 = 发行侧归属 = 项目利润 × 50%。两侧相加等于项目利润 |
| 亏损 | 项目利润 ≤ 0 时，两侧归属都是 0，详情里展示亏损，不出现正向分成 |
| 出售、外部服务 | 不套五五。只展示该类自己的金额、确认收入、回款、项目利润 |
| 归属性质 | 内部归属。不从公司经营利润里再减一次，也不做成现金激励 |
| 现金激励 | 本期固定为 0，卡片写「本期无实际支付」 |
| 三类金额不能相加 | 自研看流水，出售看合同额，外部服务看客户预算。这三列都不进入公司营业收入 |
| 公司确认收入 | 三类业务的确认收入之和 |
| 预算达成 | 期间经营利润 ÷ 期间经营利润预算。预算为 0 时显示「—」 |
| 支撑月数 | 可动用现金 ÷ 近 3 个完整月的月均净支出。净支出 = 投放 + 研发投入 + 其他直接成本 + 人工 + 管理 − 回款 |
| 老游戏 | 生命周期为成熟期、衰退期的游戏 |
| 新项目 | 生命周期为测试期、成长期的游戏 |
| 覆盖差额 | 老游戏期间经营利润 − 新项目期间（研发投入 + 发行投放）。演示数据没有现金流水账，这是经营利润近似，卡片上必须写明 |

现有「现金缺口」（预付余额 + 应收未收）保留在数据层，不放回页面，也不改名叫可动用现金。

## 3. 这一期不写

- 个人结算额，以及按人推算谁创造了利润。
- 风险责任人、期限、决策状态、验证结果。
- 退款、坏账、分配规则版本、追溯调整。
- 净利润、公司留存利润。
- 未签约意向、完整排期、支持部门服务质量。
- 活跃、付费、留存看板。游戏行继续只用现有的生命周期。
- 获客成本、LTV。继续用累计预估 ROI、回本天数、投放回收曲线。
- 公共费用分摊前后的第二套利润。
- 把算法说明、置信度推导放回网页。

## 4. 实施步骤

按顺序做。每一步结束都要能 `npm run typecheck` 通过，再进下一步。

### 步骤 1 · 扩类型，不改页面

文件：`src/domain/types.ts`、`src/composables/useAnalysisFilter.ts`。

1. 新增 `export type BusinessType = 'self_op' | 'sale' | 'external'`。
2. `DimKey` 增加 `'businessType'`。
3. `AnalysisFilter` 增加 `businessTypes: BusinessType[]`。空数组表示三类都看。
4. `store.defaultFilter()` 里该字段默认 `[]`。
5. `useAnalysisFilter` 的 `hasFilter` 把 `businessTypes.length` 算进去。
6. `Metrics` 增加下面这些字段。所有现有聚合路径都要赋值，用不到的节点填 `0`。支撑月数和可动用现金只在公司节点有意义，其他节点填 `null` 用单独可选字段，避免树表把各级现金加总。

| 字段 | 含义 | 节点 |
|---|---|---|
| `grossAmount` | 流水 / 合同额 / 客户预算，展示名随业务类型变 | 各类业务 |
| `cashCollection` | 回款 | 各类业务 |
| `rdInvest` | 研发投入 | 各类业务 |
| `otherDirectCost` | 其他直接成本 | 各类业务 |
| `projectProfit` | 项目利润 | 各类业务 |
| `rdShare` | 研发侧内部归属 | 仅自研且盈利时非 0 |
| `issueShare` | 发行侧内部归属 | 同上 |
| `budgetProfit` | 期间经营利润预算 | 公司与三类业务 |
| `profitAttainment` | 经营利润 ÷ 预算 | 预算为 0 时页面显示「—」 |
| `availableCash` | 可动用现金 | 仅公司，其余 `null` |
| `runwayMonths` | 支撑月数 | 仅公司，其余 `null` |
| `matureProfit` | 老游戏期间经营利润 | 公司，以及能拆到游戏的节点 |
| `newProjectNeed` | 新项目研发投入 + 发行投放 | 同上 |

`buildMetrics()` 的返回值补齐这些字段，旧页面只是多几个用不到的数，行为不变。

### 步骤 2 · 写演示用业务记录

文件：`src/domain/dimensions.ts`。

1. 增加 `BUSINESS_DEALS`。每条记录固定这些字段：`id`、`businessType`、`gameId`、`projectId`、`name`、`contractOrBudget`（出售为合同额，外部服务为客户预算；自研这条为 0，流水仍从现有投放数据来）、`recognizeRatio`（确认为收入的比例）、`collectRatio`（已回款占确认收入的比例）。
2. 数量：出售 4 条、外部发行投放 4 条。挂到现有游戏上，不新建一套组织。
3. 自研运营不另造收入。现有应确认收入、已到账收入、投放消耗继续代表自研。自研的 `grossAmount`（流水）用现有应确认收入按游戏变现类型乘一个固定系数，系数写在维度文件里，并且不等于 1，这样流水和确认收入不会显示成同一个数。
4. 出售、外部服务的确认收入 = 合同额或客户预算 × `recognizeRatio`。回款 = 确认收入 × `collectRatio`。两条比例都小于 1，用来摆出「签了但没全部确认、确认了但没全部回款」。
5. 研发投入：自研按现有人工成本里能归到该游戏的部分；归不到游戏的研发中心成本留在组织轴，不塞进某一个游戏。出售项目另给一笔固定研发投入。外部服务的研发投入为 0。
6. 其他直接成本：三类都给一笔远小于投放和研发的固定额，只为了成本饼图多出这一块。

### 步骤 3 · 在 store 里汇总，并保证加总得上

文件：`src/domain/store.ts`。

1. `queryRows(filter, 'businessType', parentId)`：父级是公司时返回最多 3 行，名称为「自研运营」「游戏出售」「外部发行投放」。`filter.businessTypes` 非空时只返回选中的类型。
2. 公司确认收入 = 自研应确认收入 + 出售确认收入 + 外部服务确认收入。
3. 合同额、客户预算、流水任何时候都不加进 `accrualRevenue` 或 `revenue`。
4. 项目利润、两侧归属按第 2 节的规则在游戏或业务记录上计算，再向上汇总。汇总后的研发归属 + 发行归属，只等于自研盈利项目的项目利润，不等于公司经营利润。
5. 经营利润公式不改：应确认收入 − 投放消耗 − 人工 − 管理。出售和外部服务的确认收入进入应确认收入，它们的投放和研发进入对应成本。内部归属不参与这条公式。
6. 预算：给公司和每一类业务各写一条年度经营利润预算，按月平均。期间预算 = 落入筛选月份的月预算之和。用固定数，不用「实际 × 系数」，避免达成率永远是同一个百分比。
7. 可动用现金写一个公司级常数。支撑月数只用公司节点、按第 2 节的近 3 个完整月计算。近 3 个月不足时显示「—」。
8. 筛选 `businessTypes` 后，上述汇总只保留选中类型。组织轴同样受这个筛选影响。
9. 在 `store.ts` 底部用开发时断言核对，刷新页面时 `console.error`，不要做新的测试框架：
   - 三类确认收入之和与公司确认收入的差小于 1 元。
   - 任一自研盈利项目的两侧归属之和与项目利润的差小于 1 元。
   - 亏损项目两侧归属都是 0。
   - 出售合同额、外部客户预算都不在公司确认收入的构成里重复出现。

## 6. 做完后的核对

本地 `npm run dev` 打开 `http://localhost:5180/#/drilldown`，按这个顺序点：

1. 公司节点第二排有预算达成、确认收入、回款、可动用现金。四张原有卡还在。
2. 业务轴展开后第一层是自研运营、游戏出售、外部发行投放。三类确认收入加总等于公司确认收入。
3. 点开一条出售记录：看得到合同额，合同额大于确认收入，确认收入大于或等于回款。合同额没有出现在公司营业收入里。
4. 点开一条盈利的自研游戏：研发归属和发行归属相等，相加等于项目利润。公司经营利润不等于这两个归属之和。
5. 点开一条亏损记录：两侧归属为 0。
6. 筛选只留「游戏出售」后，树和详情里不再出现自研流水。清空筛选后恢复。
7. 模拟预估里当月有预算达成，滚动图能看出三类利润，资金卡片有支撑月数和覆盖差额，口径那两句话在卡片上。页面上没有「现金缺口」四个字，也没有算法公式。
8. 直接打开 `/#/settings` 仍进入经营数据看板。
9. `npm run typecheck` 通过。
